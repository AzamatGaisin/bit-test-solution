# Таблица сделок

Тестовое задание для старшего специалиста отдела автоматизации.

[Открыть демо](https://www.bwd-studio.ru/bit_test_solution/)

[Репозиторий GitHub](https://github.com/AzamatGaisin/bit-test-solution)

PHP получает данные одним GET-запросом к n8n и выводит таблицу. n8n запрашивает список ID, загружает каждую сделку и собирает общий ответ.

## Файлы

```text
├── php/
│   └── index.php
├── n8n/
│   └── workflow.json
└── README.md
```

Нужны PHP 8.2 или новее с расширением cURL и n8n. Workflow проверен в n8n 2.45.5. Стили Bootstrap подключаются через CDN.

## Запуск

1. В n8n создайте workflow, выберите Import from File и загрузите `n8n/workflow.json`.
2. Откройте узел «Настройки API». В нем уже заполнены адрес сервиса, пути методов и тайм-аут:

   ```text
   baseUrl: https://run.mob-edu.ru
   listPath: /webhook/api/test.task/get.element.list
   detailPath: /webhook/api/test.task/get.element
   timeoutMs: 10000
   ```

3. Сохраните workflow и нажмите Publish. В версиях n8n с переключателем Active включите его.
4. Скопируйте Production URL из узла «Получить сделки» и укажите его в `N8N_WEBHOOK_URL` при запуске PHP.

Пример для Windows PowerShell, из корня проекта:

```powershell
$env:N8N_WEBHOOK_URL = 'http://127.0.0.1:5678/webhook/api/test.task/get.deals'
php -S 127.0.0.1:8080 -t php
```

Linux или macOS:

```bash
N8N_WEBHOOK_URL='http://127.0.0.1:5678/webhook/api/test.task/get.deals' php -S 127.0.0.1:8080 -t php
```

Откройте `http://127.0.0.1:8080`. Если переменная не задана, PHP использует приведенный выше локальный адрес. Проверить наличие cURL можно командой `php --ri curl`.

В поле Path у webhook указано `api/test.task/get.deals`. Префикс `/webhook/` n8n добавляет сам. Адрес `/webhook-test/` нужен для ручного тестирования и для постоянной работы страницы не подходит.

Если n8n еще не установлен, для локальной проверки можно выполнить `npx n8n@2.45.5` в совместимой версии Node.js и открыть `http://localhost:5678`. При первом запуске n8n предложит создать учетную запись.

Для постоянного размещения PHP нужен веб-сервер. Если PHP и n8n работают в разных контейнерах, в `N8N_WEBHOOK_URL` укажите имя сервиса n8n в общей сети. `localhost` внутри PHP-контейнера ведет в сам контейнер.

В опубликованном демо PHP и n8n работают на сервере. Компьютер с локальной установкой для просмотра демо не нужен.

## Как работает решение

Узел «Список ID» вызывает `get.element.list`. «Проверить список» разбирает ответ, проверяет идентификаторы и убирает повторы. Неверные элементы записываются в ошибки.

«Подготовить ID» создает отдельный элемент для каждой сделки. HTTP Request выполняет запрос `get.element?id=...` для каждого входного элемента, поэтому отдельный цикл не нужен.

В HTTP-узлах включены Never Error и On Error: Continue. Это позволяет обработать HTTP-ошибку, тайм-аут или обрыв соединения и продолжить загрузку остальных сделок. Ответ читается как текст, чтобы ошибка разбора JSON тоже попадала в общий результат.

«Собрать ответ» проверяет поля каждой сделки и переносит нужные данные в `data`. При ошибке сохраняются исходный ID и причина. Связь с исходным ID берется через `itemMatching`, поэтому сетевой сбой не сдвигает соответствие между сделками и ответами.

Пустой список идет по отдельной ветке. Это нужно, чтобы n8n вернул JSON даже тогда, когда нет элементов для дальнейшей обработки.

PHP делает ровно один запрос к webhook. Затем проверяет ответ, проходит по `data` через `foreach` и строит таблицу Bootstrap. Перед выводом строки обрабатываются `htmlspecialchars`. Суммы выводятся с двумя знаками после запятой. Валюта не добавлена, поскольку в контракте ответа нет такого поля.

## Ответ и обработка ошибок

Формат ответа:

```json
{
  "success": true,
  "total": 1,
  "data": [
    {
      "id": 1001,
      "title": "Сделка с ООО Ромашка",
      "amount": 1250000,
      "responsible": { "id": 12, "name": "Иван Петров" },
      "company": { "id": 78, "name": "ООО Ромашка" }
    }
  ],
  "errors": []
}
```

`total` равен длине `data`. `success` равен `true`, если ошибок нет. Если часть сделок не загрузилась, `success` будет `false`, доступные сделки останутся в таблице, а над ней появится предупреждение.

Пример элемента `errors`:

```json
{
  "id": 1001123,
  "code": "HTTP_ERROR",
  "message": "Сделка с ID 1001123 не найдена",
  "status": 400
}
```

Полный, частичный и корректный пустой результат возвращаются с HTTP 200. Если не удалось получить список ID или не загрузилась ни одна запрошенная сделка, webhook возвращает HTTP 502. У ошибки всего списка `id` равен `null`.

Тайм-аут одного запроса к API составляет 10 секунд, выполнения workflow 45 секунд, ожидания PHP 60 секунд. Детали сделок запрашиваются группами по 5 с интервалом 200 мс. Повторных запросов при сбое нет.

## Проверка

Проверены импорт и выполнение workflow в n8n, а также вся цепочка PHP -> n8n -> API. Реальный сервис возвращает 10 сделок. На временном API проверены пустой список, частичные и полные отказы, HTTP-ошибки, сетевые сбои, тайм-аут, поврежденный JSON и неверные поля. Отдельно проверены экранирование HTML и количество запросов из PHP.

Синтаксис PHP можно проверить командой:

```bash
php -l php/index.php
```

После публикации workflow проверьте его ответ:

```bash
curl -i http://localhost:5678/webhook/api/test.task/get.deals
```

Для проверки частичной загрузки на копии workflow добавьте после «Проверить список» временный Code-узел и соедините его с «Есть ID»:

```javascript
const item = $input.first();
item.json.ids.push(1001123);
return [item];
```

Доступные сделки должны остаться в `data`, а ID 1001123 появиться в `errors`. После проверки удалите временный узел. В документации API для отсутствующей сделки указан HTTP 404, но при проверке сервис вернул 400. Оба ответа обрабатываются как ошибка конкретной сделки.
